# Example 07: WASI 0.3 CLI とファイルシステムの読み書き

標準の `wasi:cli/run@0.3.0` をエクスポートする WASI 0.3 コンポーネントを Chicory 上で実行するサンプルです。コマンドライン引数、環境変数、標準入力、マウントしたディレクトリへのファイル読み書きを組み合わせます。

## 対象となる WIT 定義

[wasi-cli.wit](../../fixtures/wasi-cli.wit) は、`wasi:cli` と `wasi:filesystem` の各インターフェースをインポートし、`wasi:cli/run@0.3.0` をエクスポートします。コンポーネント内のプログラムは第 1 引数を入力ファイルパス、第 2 引数を出力ファイルパスとして解釈します。

プリオープンされた `/work` ディレクトリから入力ファイルを読み込みます。空行を除いた各行に環境変数 `TAG` の値と行番号を付与します。標準入力にデータがある場合は末尾へコメント行を追加し、出力ファイルへ書き出します。最後に処理件数を標準出力へ報告します。

## Gradle の設定

[build.gradle.kts](build.gradle.kts) では `wasm2kt` 拡張ブロックで `addWasiDependency.set(true)` を指定しています。この設定により `runtime-wasi` ライブラリが依存関係へ自動追加されます。また、`runtime-wasi` が持つ WASI インターフェースマニフェストが検出され、WASI 型やホストバインディングの重複生成がスキップされます。

[Main.kt](Main.kt) で設定している WASI 0.3 ホスト機能は次のとおりです。

- コマンドライン引数の受け渡し
- 環境変数マップの構成
- 文字列からの標準入力ストリーム供給
- 標準出力と標準エラーのバッファリング
- 読み書き可能なディレクトリのマウント
- 終了コードの正規化

ホストコードでは `wasi03Imports` ビルダを使って CLI 環境を構築しています。`stdin` に文字列を直接渡せるオーバーロードを使用し、UTF-8 バイト列への変換を省略しています。`mounts` ブロック内では `readWrite` を指定し、一時作業ディレクトリをゲスト側の `/work` へ公開しています。

セッション実行部は `runWasiCommand` ヘルパで囲んでいます。`run` が正常終了を返せば `0`、エラーを返せば `1` に変換されます。ゲストが `wasi:cli/exit` を呼び出して `WasiExitException` を送出した場合はその終了コードを取り出します。

## 実行手順

ビルドを行う前に、`fixtures/wasi-cli.wasm` をサンプルディレクトリ直下へ `wasi-cli.wasm` としてコピーしてください。

```bash
cp ../../fixtures/wasi-cli.wasm .
./gradlew run
```

実行に成功すると、標準出力に次の結果が表示されます。

```text
exitCode = 0
stdout = wrote 3 line(s) from input.txt to output.txt tag=cli
outputFile =
[cli] 1: first item
[cli] 2: second item
[cli] 3: third item
# footer: generated by 07-wasi-cli
```
