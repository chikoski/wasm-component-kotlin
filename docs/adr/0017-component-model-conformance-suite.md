# 0017. Component Model の公式テストスイートを写して取り込み、既知の失敗をスキップリストで管理する

* ステータス: 承認
* 日付: 2026-11-04
* 関連: ADR-0007、#30、#16、#70、#71

## 背景

Chicory バックエンドの検証は、Wasmtime との差分テストと、Chicory 単体のテストが中心だった。この方法では、Wasmtime と挙動が違う項目（ADR-0007）について、仕様の正解を外部の基準で確かめられない。
仕様リポジトリには、`.wast` 形式の公式テストがある（`test/values`、`test/resources`、`test/async` など）。#16（async）の受け入れ基準にも使う予定である。

## 検討した選択肢

**テストの取り込み方**

1. **git サブモジュール** — 正本との対応が明確 / clone のたびに初期化が要る。CI と Gradle の設定が増える
2. **ビルドのときにダウンロードする** — リポジトリが大きくならない / CI がネットワークに依存する。オフラインでテストできない
3. **決まったコミットの `test/` をリポジトリに写す（vendoring）** — 追加の設定が要らない。差分がレビューできる / 1.5 MB 増える。更新はスクリプトで行う

**既知の失敗の扱い**

1. 失敗をそのままにする — CI が赤のままになる
2. **理由つきのスキップリスト** — 失敗の理由と Issue を残せる。通るようになったら気づける

## 決定

* テストは選択肢 3（写す）で取り込む
  * 置き場所は `conformance/component-model/`。コミットとライセンス（Apache 2.0）も一緒に置く
  * 更新は `conformance/update.sh <コミット>` で行う
* `.wast` は、`wasm-tools json-from-wast` で変換する。CI と同じ 1.258.0 で、今のコミットのファイルは 78 個中 74 個を変換できた。変換できないうち 3 個は、仕様の `nyi.txt` に載っている
* ハーネスは integration-tests の `ConformanceTest` に置く
  * コンポーネントは同梱の decomposer で分解し、Chicory のインタプリタで実行する。AOT コンパイルは通さない（Canonical ABI の処理は同じなので、適合性の確認には要らない）
  * 値は、テストの JSON（型の付いた値）と、バイナリ形式（ADR-0015）の間で変換する。型は plan から取る
  * `assert_trap` は `ComponentTrapException` になることだけを確かめる。メッセージは実装ごとに違うので比べない
* 既知の失敗は `conformance/skip.txt` に、ファイル単位か行単位で、理由と Issue の番号を付けて書く
  * 仕様の `nyi.txt` も飛ばす
  * 載せたものが通ったら、テストを失敗にする（リストを最新に保つため）
* 対象のディレクトリは、まず `values/` と `resources/` にする
  * `async/` は #16 で加える
  * `validation/`（不正なコンポーネントの拒否）、`linking/`、`binary/` は後で検討する
* Wasmtime バックエンドでは実行しない。Wasmtime 自身が同じスイートを実行しているので、価値が小さいため。ただし、汎用ブリッジの値の変換を確かめたくなったら、ハーネスのバックエンドを差し替えられる形にしておく

## 結果

* 取り込んだ時点（コミット c818a19）の結果: 191 のコマンドのうち、168 が通り、23 をスキップした
  * スキップには、`nyi.txt` に載ったファイルと、作れなかったコンポーネントに対するコマンドも含む
* 見つかった問題と、その扱い
  * 型を export するコンポーネントは、WIT に直せないので分解が失敗していた。decomposer が `wit.json` の代わりに `wit-error.txt` を書くように直した。実行には plan だけが要るので、こうしたコンポーネントも動く
  * 合成したコンポーネントの間で resource を受け渡す組み込み関数は、Chicory にない（#70）
  * `map<K, V>` 型（#71）
  * async の lift（#16）
* 仕様の新しいテストを取り込むには、`update.sh` を実行し、`skip.txt` を見直す
