# 0004. ビルド時ツールを Gradle ワーカーの独立クラスローダーで実行する

* ステータス: 承認
* 日付: 2026-10-30

## 背景

最初の実装ではプラグインがツール群（Chicory のコンパイラ、ASM、KotlinPoet）を直接クラスパスに持っていた。
Android プロジェクトでは AGP の古い ASM が優先され、`Remapper.<init>(int)` が見つからずにビルドが失敗した。

## 検討した選択肢

1. **シャドウ（リロケーション）した fat jar にする** — 依存を外に出さない / ビルド設定が複雑になり、Chicory 内部のクラス生成とリロケーションの相性リスクがある
2. **Gradle Worker API の `classLoaderIsolation` で実行する** — Gradle 標準の方法 / ツールの依存を利用側で解決する必要がある

## 決定

選択肢 2。プラグインは `tooling` を compileOnly に留め、利用側プロジェクトに `wasm2ktTooling` 構成（既定は
`io.github.wasm2kt:tooling:<プラグインと同じバージョン>`）を作って、ワーカーの独立クラスパスとして使う。
設定時（configuration time）に tooling のクラスを参照してはならない。

## 結果

* AGP など、ほかのプラグインと依存が衝突しない
* 利用側に tooling とその依存を解決できるリポジトリ（mavenCentral）が必要。公開（A-7）が前提になる
* プラグイン側で必要な純粋関数（例: 内部パッケージ名の計算）は、tooling と二重に持つことになる。両者が一致している必要がある
* Kotlin プラグインの型も、クラスローダーが分かれると見えなくなることがあるため、Gradle API とリフレクションで扱う
